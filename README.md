# strata_mem

## 项目介绍

L3缓存是处理器缓存体系中的第三级缓存，容量通常大于L1、L2缓存，访问速度快于主存。它用于保存近期访问或可能再次访问的数据，使处理器能够直接从缓存中获取数据，减少对主存的访问。当所需数据不在L3缓存中，且其他缓存也无法提供时，通常需要从主存读取，从而增加访问时延和主存带宽开销。

L3缓存由多个缓存组构成，每个缓存组能够容纳的数据量有限，数据在其中的存放位置受硬件映射规则约束。硬件根据内存地址确定数据对应的缓存位置。如果多个地址的数据集中映射到同一个缓存组，就可能相互竞争，导致已有数据被提前淘汰。因此，即使程序访问的数据总量小于L3缓存的总容量，也可能出现缓存未命中，进而访问主存。

针对内存地址分布可能引发的缓存组竞争问题，strata_mem提供基于大页内存和固定物理偏移布局的内存申请与释放接口，通过校验大页物理地址、按物理地址排序并按预设偏移选取内存区域，构建固定布局的数据缓冲区。同时，项目提供多线程访问测试，支持CPU绑核、预热和吞吐测量，可配合外部监控工具分析内存地址分布对L3缓存访问的影响，为缓存访问优化提供实验依据。

## 环境部署

### 环境要求

| 项目 | 要求                                         |
| --- |--------------------------------------------|
| OS      | openEuler 22.03 LTS SP4                    |
| 处理器 | 华为鲲鹏920新型号处理器                              |
| 大页资源 | 每次分配需要32个空闲1GiB大页，占用32GiB，另需为系统和其他业务保留内存 |

### 编译

在项目根目录执行：

```sh
make -j
```

生成以下文件：

- `build/libl3_mem.a`：内存接口静态库。
- `build/l3_mem_test`：固定布局访问测试程序。

编译过程不申请大页。编译完成后，可先查看参数帮助，该命令不会申请测试内存：

```sh
./build/l3_mem_test --help
```

### 运行前检查

由服务器管理员按实际内存容量和NUMA策略预留1GiB大页。程序不会自动修改系统大页预留量。以下命令以node 0为例查看资源和CPU拓扑：

```sh
cat /sys/devices/system/node/node0/hugepages/hugepages-1048576kB/nr_hugepages
cat /sys/devices/system/node/node0/hugepages/hugepages-1048576kB/free_hugepages
lscpu
numactl --hardware
```

使用`--membind=0`时，应确认node 0至少有32个空闲1GiB大页。其他节点请替换对应路径和节点编号；未安装`numactl`时可省略相关命令，接口将继承调用进程已有的NUMA策略。

并发运行多个实例会分别占用32GiB。首次触碰大页仍可能因资源不足触发`SIGBUS`，程序没有安装该信号的恢复处理。初始化包含全量清零和逐页物理地址检查，完成前可能需要等待。

## 开发指南

### 规格约束

- 接口采用C++17实现，声明位于[src/l3_mem.h](src/l3_mem.h)，命名空间为`l3mem`。使用时需包含该头文件并链接`build/libl3_mem.a`。
- 实际内存申请要求64位Linux，支持1GiB HugeTLB大页，并具备大页分配和读取`/proc/self/pagemap`真实页帧号所需权限。
- 每次申请固定映射32个1GiB大页，共占用32GiB连续虚拟地址空间；各大页之间不要求物理连续。不支持通过接口修改容量，也不提供普通页或其他大页尺寸的自动回退。
- 接口对整个32GiB映射清零，逐基础页检查每个大页内部的物理连续性，再按大页物理地址排序。排序不会移动内存，也不会改变原始映射地址。
- 按内置的`seed35-fixed-v1`布局返回70个区域，每个区域为1MiB，总工作集为70MiB。区域的排序页编号和页内偏移固定，绝对物理地址和虚拟地址随实际分配变化；各区域不保证彼此连续。
- 内存分配继承调用进程的NUMA策略，接口内部不强制绑定节点。每次独立申请均占用32GiB，调用方需提前准备足够的大页资源。
- 描述结构体不自动释放内存，复制结构体也不会产生新的分配或释放权。调用方必须指定唯一的释放责任方，并在所有CPU/DMA访问停止、外部设备内存注销完成后释放原始映射。
- 接口不执行SPDK/RDMA内存注册，也不保证L3驻留或缓存命中率提升，实际缓存效果需在目标服务器上验证。

### 对外接口

#### malloc_l3

**函数定义**

申请并初始化固定布局的内存缓冲区，接口类型为同步接口。完成大页映射、全量清零、物理地址校验和区域填充后返回。

**实现方法**

以下声明位于`l3mem`命名空间中：

```cpp
[[nodiscard]] L3Buffer malloc_l3() noexcept;
```

**参数说明**

无入参。

**返回值**

- 成功：返回有效的`L3Buffer`，`valid()`为`true`，包含原始映射地址及70个可访问区域。字段定义请参见[结构体](#l3mem-structures)。
- 失败：返回空的`L3Buffer`，`valid()`为`false`，并设置`errno`。调用方应立即保存错误码。

#### free_l3

**函数定义**

整体释放`malloc_l3()`申请的32GiB映射，接口类型为同步接口。调用前必须停止所有相关内存访问并完成外部设备内存注销。

**实现方法**

以下声明位于`l3mem`命名空间中：

```cpp
[[nodiscard]] bool free_l3(void* base_address) noexcept;
```

**参数说明**

| 参数名          | 数据类型  | 参数类型 | 描述                                                              |
|--------------|-------|------|-----------------------------------------------------------------|
| base_address | void* | 入参   | malloc_l3()返回的L3Buffer::base_address，必须是原始且仍有效的映射地址；允许传入nullptr |

**返回值**

- `true`：释放成功；传入`nullptr`时不执行操作，也返回`true`。
- `false`：释放失败，并设置`errno`。地址未按1GiB对齐时设置`EINVAL`；非Linux平台传入非空地址时设置`ENOTSUP`；解除映射失败时保留`munmap`设置的错误码。

**使用约束**

接口不维护分配登记，地址对齐检查不能验证映射所有权。不得传入区域地址、其他映射的地址，或对同一次分配重复释放、并发释放。

释放成功后，所有相关区域指针以及结构体副本中的地址均失效。接口按值接收地址，不会自动清空调用方的描述结构体，建议在成功后执行`buffer = {};`。释放失败时应保留原始地址并处理错误。

### 结构体<a id="l3mem-structures"></a>

以下结构体均定义于`l3mem`命名空间，完整定义见[src/l3_mem.h](src/l3_mem.h)。

#### L3Region

描述单个可访问的内存区域。

```cpp
struct L3Region {
    void* address = nullptr;
    std::size_t size = 0;
};
```

| 字段名     | 数据类型        | 描述                                   |
|---------|-------------|--------------------------------------|
| address | void*       | 区域起始虚拟地址，默认值为nullptr                 |
| size    | std::size_t | 区域长度，单位为字节，默认值为0；申请成功后为1048576（1MiB） |

#### L3Buffer

描述一次完整分配及其选定区域。该结构体不负责自动管理映射的生命周期。

```cpp
struct L3Buffer {
    void* base_address = nullptr;
    std::array<L3Region, kRegionCount> regions{};

    [[nodiscard]] bool valid() const noexcept {
        return base_address != nullptr;
    }
};
```

| 字段名          | 数据类型                               | 描述                                           |
|--------------|------------------------------------|----------------------------------------------|
| base_address | void*                              | 原始32GiB映射的起始虚拟地址，用于整体释放；不等同于按物理地址排序后的第一个大页地址 |
| regions      | std::array<L3Region, kRegionCount> | 固定包含70个区域，数组下标为区域编号，申请成功后各区域大小均为1MiB         |

`valid()`无入参，返回`bool`，仅检查`base_address`是否非空，不检查映射是否仍然存在。因此，释放后未清空的结构体或其副本不能通过该方法判断地址是否仍可访问。

相关常量定义如下，类型均为`std::size_t`：

| 常量名            | 值                  | 说明                     |
|----------------|--------------------|------------------------|
| kHugePageCount | 32                 | 每次申请的大页数量              |
| kHugePageSize  | 1073741824（1GiB）   | 单个大页的字节数               |
| kMappingSize   | 34359738368（32GiB） | 完整映射的字节数               |
| kRegionCount   | 70                 | 返回的区域数量                |
| kRegionSize    | 1048576（1MiB）      | 单个区域的字节数               |
| kBufferSize    | 73400320（70MiB）    | 所有返回区域的总字节数，不代表连续缓冲区长度 |

## 快速入门

项目提供的[test/l3_mem_test.cpp](test/l3_mem_test.cpp)可直接作为入门用例，演示内存申请、区域访问和释放的完整流程。运行前请完成[环境部署](#环境部署)中的编译和资源检查。

测试程序通过`l3mem::malloc_l3()`申请内存，使用`buffer.valid()`检查申请结果，再将`buffer.regions`分配给工作线程进行预热和测量。测试结束并等待工作线程退出后，通过`l3mem::free_l3(buffer.base_address)`释放映射。接口定义及使用约束请参见[开发指南](#开发指南)。

### 运行固定布局访问测试

以下示例使用node 0的内存，启动14个线程，每线程访问5个区域，预热10秒后测量10秒：

```sh
numactl --membind=0 ./build/l3_mem_test \
  --threads 14 --rounds 1 --warmup 10 --seconds 10
```

默认绑定CPU0 ~ 13，请根据实际CPU访问权限、NUMA拓扑和SMT关系调整。CPU不可用时，程序会在申请大页前报错。显式CPU列表需使用逗号分隔且数量等于线程数，编号不得重复，不支持范围语法：

```sh
numactl --membind=0 ./build/l3_mem_test \
  --threads 7 --cpus 0,2,4,6,8,10,12 --warmup 10 --seconds 90 --rounds 3
```
